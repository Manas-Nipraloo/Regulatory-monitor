Regulatory Monitor - Session Summary
Date: 06-07-2026

Project Goal
- Build a Python/FastAPI regulatory monitor app.
- Daily workflow:
  1. Visit configured regulatory websites.
  2. Find current-date articles/documents.
  3. Download/process PDF documents.
  4. Upload only PDFs to Google Drive in date/remark folders.
  5. Extract headings and summaries.
  6. Draft an email in the required format.
  7. If no articles are found, do not upload anything and do not create an email draft.

Current Pending-Review / Email Behavior

- Accept does NOT create the Hostinger draft immediately.
- The combined draft is created only when clicking Build all accepted.
- Build all accepted was changed to ignore the dashboard date and build from all accepted items by default.
- Source filtering for Build all accepted is still kept.

Important Behavior Fixes
- Removed the bad behavior where many PDFs could inherit the exact same heading/summary from one parent article title.
- Removed raw PDF filename fallback as a visible heading.
- If extracted heading is unusable, heading now falls back to the cleaner source/article title instead of a machine-style filename.
- Summary fallback still shows a neutral review-needed message when extraction is unreadable.
- Added filtering so index/table-of-contents lines like "1.1 ..." or numbered annexure lists are less likely to become headings.

Groq / PDF Extraction State
- Scanned/image PDFs now allow Groq to inspect at least 5 pages.
- Text PDFs now send a broader text sample to Groq:
  beginning + middle + end of the document instead of only the opening chunk.
- Groq prompt was tightened to ignore annexure labels, address blocks, CIN/registered-office text, and page furniture.
- Extraction is still imperfect for some annexure-heavy PDFs and may need further tuning.

Known Current PDF Extraction Issues
- Some annexure or scanned PDFs still produce weak headings/summaries.
- If the first pages are a contents/index page, extraction can still be imperfect even after filtering.
- Good ChatGPT-style summaries are still better than the current automated extractor in some documents.

Current MCA / Playwright Problem
- MCA sources fail because Playwright is unavailable in the environment.
- Root cause identified from Playwright install output:
  missing Windows dependency msvcp140_1.dll
- This means Microsoft Visual C++ Redistributable (x64) must be installed.
- Python 3.14 was avoided; a new Python 3.12.10 environment was created instead.
- Even in Python 3.12, Playwright still needs the missing VC++ runtime before MCA can work.

Exact MCA Error Meaning
- "Playwright is unavailable in this Python environment. MCA discovery requires a working Playwright install."
- This is not a scraper logic bug.
- It is an environment/runtime dependency issue.

2. Open a fresh PowerShell window.
3. Activate .venv.
